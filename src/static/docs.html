Overview

Keystone is a self-hosted, content-addressable file platform. Every file is stored under its SHA-256 hash, so duplicate uploads are automatically de-duplicated (the same bytes occupy one storage slot, referenced by many user files). It is API-first: every UI action calls a JSON HTTP API.

Core concepts

  • Storage paths — physical directories (disks/mounts) configured via STORAGE_LOCAL_PATHS. The first is the default for new uploads.
  • Backends — a logical storage location mapped to a storage path.
  • Buckets — top-level namespaces users are granted access to. Each bucket maps to a directory on disk.
  • Groups — permission bundles (bucket access, roles, quotas) applied to users.
  • User files / folders — the metadata tree; content lives once in the hash store.

The UI is fully self-contained (Vendored Alpine.js + Tailwind, embedded SVG logo) — no CDN dependency, works offline behind firewalls.

Storage Layout

Files land on disk at:

$STORAGE_LOCAL_PATHS/<storage-path-slug>/<bucket-name>/<blake3-shards>/<blake3-hash>

The hash is sharded into two-byte prefix directories (fc/bd style) to avoid huge flat directories. Example with the Docker default:

# inside the server container:
/mnt/keystone/data/test1/test1/fc/bd/a3f...c19   (bucket "test1", backend "test1", file hash a3f...)

# on the Docker host (default setup — named volume):
/var/lib/docker/volumes/keystone_storagedata/_data/test1/test1/fc/bd/a3f...c19

Where the folder lives on your PC: set DATA_HOST_PATH in .env to choose the host-side half of the mount. The server always sees /mnt/keystone/data (or STORAGE_LOCAL_PATHS) — only the outside half changes:

  • DATA_HOST_PATH= (empty) — Docker named volume storagedata (default; hidden under /var/lib/docker/volumes/keystone_storagedata/_data).
  • DATA_HOST_PATH=./data — a real folder next to the project (<project>/data), visible and easy to back up. Relative paths are anchored to the project root by ./docker-run.sh.
  • DATA_HOST_PATH=/any/absolute/path — bind mount to that exact host path, e.g. a second disk.

Switching (e.g. volume → ./data): copy existing files once with docker run --rm -v keystone_storagedata:/from -v "$PWD/data":/to alpine sh -c 'cp -a /from/. /to/ && chown -R 1000:1000 /to', set DATA_HOST_PATH=./data, restart, then verify before removing the old volume.

Key rules:

  • STORAGE_LOCAL_PATHS entries must be absolute paths inside the server container. The compose stack mounts ${DATA_HOST_PATH:-storagedata} at /mnt/keystone/data.
  • Keep the container-side path stable forever — the database stores absolute paths (e.g. buckets.path = /mnt/keystone/data/test1/test1). Changing the mount target requires a data migration; changing DATA_HOST_PATH (the mount source) does not.
  • storage_objects.storage_path is relative (backend-relative); buckets.path and storage_paths.path are absolute.

Migration 0015_storage_root_mount rewrote legacy /data/storage prefixes to /mnt/keystone/data. Verify with:

docker exec keystone-postgres psql -U keystone -d keystone -c \
  "SELECT name, path FROM buckets; SELECT slug, path FROM storage_paths;"

Name Validation Rules

Files, folders, and bucket names are validated server-side (src/utils/names.rs) so every name is safe on all major OS filesystems. A name is rejected if it:

  • is empty, or equals . or ..
  • contains control characters (newline, tab, etc.)
  • contains any of \ / : * ? " < > |
  • starts with a space, or ends with a space or a dot
  • exceeds 255 bytes
  • is a Windows reserved device name, case-insensitive (with or without extension): CON PRN AUX NUL COM1-9 LPT1-9

The same rules are mirrored in the browser UI (validateName) so invalid names are caught before upload. Admin imports (folder resolution + file names) are validated too — an import is skipped per-item rather than failing wholesale.

Why: a folder named CON or a file named bad:name is legal on Linux but impossible or dangerous on Windows/macOS, and breaks syncing tools. Enforcing one strict, portable rule set keeps the platform usable everywhere.

URL Deep Links

The Files UI keeps the current location in the URL so pages can be bookmarked and shared:

/files?dir=/                Root of your current bucket
/files?dir=/test             Folder "test" at the root
/files?dir=/test/hello       Nested folder "hello" inside "test"
/files?dir=/test/hello/      Trailing slash is normalized
  • dir=/ means the bucket root; dir=/test resolves the first folder named test at the root of your effective bucket.
  • The effective bucket comes from the in-app bucket selector (persisted per browser). A bucket can also be forced with the legacy ?bucket_id=&path= parameters.
  • Breadcrumb clicks, folder opens, and bucket switches rewrite the URL via history.replaceState — no reload.
  • Refreshing or pasting a deep link re-resolves the path server-side and restores pagination/search. If the folder no longer exists, the UI falls back to the root.

File Preview

  • Double-click an image or video file (list or grid view), or use right-click → View, to open an inline preview.
  • Images render in a modal; videos play with an inline player. A download button is available in the preview header.
  • The UI loads previews through the /api/files/:id/raw endpoint (same access rules as download), so no separate permission is needed.
  • Non-media files still download on double-click.

Docker Operations

Rebuild and deploy

docker compose -p keystone --env-file .env -f docker/docker-compose.yml up -d --build

Logs / status

docker compose -p keystone -f docker/docker-compose.yml logs -f server
docker exec keystone-postgres psql -U keystone -d keystone -c "SELECT version();"

Backup

Two things must be backed up together — they are the same backup unit:

  • The database — metadata, users, buckets, permissions: 
    docker exec keystone-postgres pg_dump -U keystone -d keystone > keystone-db.sql
  • The storage — all content-addressed bytes. If DATA_HOST_PATH is empty (default named volume): 
    docker run --rm -v keystone_storagedata:/data -v "$PWD":/backup alpine \
  tar czf /backup/keystone-storage.tgz -C /data .
    If DATA_HOST_PATH points at a folder (./data etc.), that folder IS your storage — just copy/tar it like any normal directory (e.g. tar czf keystone-storage.tgz data/).

Restore by replaying the dump into a fresh Postgres and unpacking the volume before starting the server. Backup the DB and storage at the same moment for a consistent snapshot.

Environment (from .env.example)

  • SERVER_PORT (default 3000), APP_ENV, SERVER_HOST
  • POSTGRES_* — bare-metal DB URL is derived from them; compose wires the server to the postgres container automatically (override with DATABASE_URL/KEYSTONE__DATABASE__URL)
  • JWT_SECRET, JWT_EXPIRY_MINUTES, REFRESH_EXPIRY_DAYS
  • ENCRYPTION_TOKEN — must be stable across restarts; rotating it invalidates encrypted values
  • STORAGE_LOCAL_PATHS (comma-separated; first is default), STORAGE_MAX_UPLOAD_SIZE_MB
  • DATA_HOST_PATH — where storage lives on the host: empty = storagedata volume, ./data = a folder in this project, or any absolute host path (see Storage Layout above)
  • WORKER_*_INTERVAL_SECS — GC, integrity verification, stats cadence
  • CORS_ALLOWED_ORIGINS

Error Format

Errors follow RFC 7807 Problem Details:

{
  "type": "/errors/NOT_FOUND",
  "title": "Resource Not Found",
  "status": 404,
  "detail": "resource not found: file not found"
}
Code HTTP Meaning
NOT_FOUND404Resource does not exist
UNAUTHORIZED401Authentication required or invalid
FORBIDDEN403Insufficient permissions
BAD_REQUEST400Invalid request body or parameters
CONFLICT409Resource already exists (duplicate)
INTERNAL_ERROR500Unexpected server error
STORAGE_ERROR500Storage backend failure
VALIDATION_FAILED422Input validation failed

Every response carries X-Request-ID (UUID) for tracing and the CORS origin header. Include the request ID when reporting issues.
